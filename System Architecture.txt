ARMA 3 MODULAR LOGISTICS FRAMEWORK

Master System Architecture Blueprint

This document tracks all framework modules, their dependencies, and their execution hooks. It ensures that components can be safely added or removed without breaking the core mission.

⚙️ THE MASTER CORE (Shared Dependencies)

These files form the foundation of the mission. Without these, the modular systems have no variables to hook into.

init.sqf (or init_MASTER.sqf)

Purpose: The main bootloader. Compiles config files and selectively boots modules if their files exist.

Called By: Arma 3 Engine (Mission Start)

description.ext

Purpose: Mission config and UI master table of contents.

Called By: Arma 3 Engine (Mission Start)

defines.hpp

Purpose: Master Base Classes for all GUIs (RscText, RscButton, etc.). Prevents duplicate definitions.

Called By: #include at the top of description.ext

logisticsCargoTemplates.sqf

Purpose: Database defining which vehicles can carry which supplies.

Called By: Compiled via init.sqf

SupplyScores.sqf & logisticsBaseDefaults.sqf

Purpose: Configures economy points and default base values.

Called By: Compiled via init.sqf

📦 PART 1: LOGISTICS TRANSPORT SYSTEM

The physical movement of supplies between bases using transport vehicles and editor-placed trigger pads.

fn_initLogisticsTasks.sqf

Purpose: Server-side script that scans the map for bases and sets up delivery tasks.

Called By: init.sqf (Executed on Server)

fn_manageLogisticsMissions.sqf

Purpose: Client-side tracking loop. Updates the player's UI/Tasks based on their vehicle and cargo.

Called By: init.sqf (Executed on Client via hasInterface)

fn_spawnLoadSupply.sqf (Formerly SpawnLoadSupply11.sqf)

Purpose: Physical deployment engine. Deducts base points and spawns cargo into the vehicle.

Called By: Eden Editor Trigger (On Activation) at Loading Pads.

fn_cargoDelivery.sqf (Formerly CargoDelivery3.sqf)

Purpose: Ground pad scanner. Deletes physical cargo and adds points to the destination base pool.

Called By: Eden Editor Trigger (On Activation) at Dropoff Pads.

🏗️ PART 2: QUARTERMASTER & SUPPLY USAGE

The UI-driven economy for recruiting troops, building vehicles, and pulling gear.

qm_quartermasterUI.hpp

Purpose: Isolated dialog definitions for the Control Hub, Motorpool, and Admin Tablet.

Called By: #include inside description.ext

qm_serverGarrisonManager.sqf & qm_serverRespawnManager.sqf

Purpose: Daemons that manage background recruitment, vehicle limits, and respawn ticket costs.

Called By: init.sqf (Executed on Server)

logisticsVehicleRoles.sqf, spawnableVehicleTemplate.sqf, virtualArsenalTemplate.sqf

Purpose: Database files detailing costs and allowed classes for factories and arsenals.

Called By: Compiled via init.sqf

🔧 PART 3: VEHICLE SERVICE SYSTEM (R4-C)

Repair, Refuel, Rearm, Recrew, and Aircraft Pylon management.

qm_pylonMenu.hpp

Purpose: Isolated dialog definition for customizing aircraft pylons.

Called By: #include inside description.ext

fn_pylonManager.sqf

Purpose: Client-side logic for parsing aircraft weapons and deducting from the Base Ammo pool.

Called By: Action menu condition (compiled in init.sqf)

qm_supplyPhysicalController.sqf

Purpose: Server-side watchdog that scans for vehicles near supply tanks/containers and processes R4-C.

Called By: init.sqf (Executed on Server)
